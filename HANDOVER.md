# Murales PDC — Handover

Last updated: 2026-11-18 (end of the "admin + polish" thread; next thread = redesign). Read this first, then `README.md` if you need the basics.

## 1. What this is
A mobile-first PWA that maps the street murals of Playa del Carmen (Quintana Roo, Mexico). Visitors browse a gallery and a map, build walking tours, like murals, and submit new murals, photos, location confirmations and "this spot has a new mural" updates. A small team (one **Owner**, optional **Moderators**) reviews submissions in `/admin`. It's a free hobby project: no ads, no accounts for visitors (**sign-in is team-only for now**), voluntary tips through a Ko-fi link (`ko-fi.com/irainpc`, side menu).

- Live: https://www.murles-pdc.art (apex `murles-pdc.art` redirects to www; the domain really is spelled "murles"; `https://pdc-art.vercel.app` also works)
- Repo: https://github.com/Rainl22/PDC-art (`main` auto-deploys to Vercel). Working branch in cloud sessions: whichever branch the session assigns (e.g. `claude/…`); fast-forward it to `main` before starting and push only there. Merge to `main` only when the owner says "merge".
- Languages: English (default) and Spanish for everything public; admin screens are English only.

## 3. How we work (read before changing things)
1. Branch/merge: commit on the working branch, open a PR to `main`, merge (merge commit). Then **confirm the Vercel deployment turns READY** (a failed deploy once went unnoticed). `mcp__Vercel__list_deployments`.
2. Before every merge run: `npx tsc --noEmit`, `npx next lint`, and a real `next build` with the two env vars set. Build-only failures happen (see gotchas).
3. UI changes are verified with Playwright against `next dev` at 390 px (Playwright + Chromium are preinstalled; tiles from OpenFreeMap and geocoders are blocked in the sandbox, so the map background is blank and geocoding is only tested with stubs). Fake GPS with `geolocation` + `permissions`; fake Supabase auth with `page.route`.
4. Database changes go through the Supabase tool (`execute_sql`) **and** get a numbered file in `supabase/migrations/` as the record (files are history, not an automatic runner; don't re-run old files). Test triggers/functions inside a `do $$ … raise exception 'ROLLBACK_TEST %', result; end $$` block so nothing is saved.
5. Never commit emails, secrets or the owner's address. The owner's email is only in the `admins` table.

## 4. Product map
### Public
- **Landing page** `/` (`src/app/page.tsx` + `landing.css`, light theme, added in a separate session): public intro page with app screenshots; the installed PWA starts at `/gallery`, the app itself lives under `src/app/(app)`.
- **Gallery** `/gallery`: each mural is a photo card with a white overlay card (name, artist, location, ≤2 tags; every line truncated so all cards are equal height). A warm soft-light tint is blended over photos (`--image-tint`, `--image-tint-opacity`). Controls: **Show** (All / Verified / Unverified / Changed) and **Sort** (Name A–Z, Artist A–Z, Recently updated = added or repainted [default], Most liked, Nearest to me — asks for location only when chosen). Both are the custom `components/ui/Select.tsx` (light dropdown, ellipsis, chevron padding). "Create tour" multi-select builds a tour. **Search box** under the title (`lib/search.ts` `matchMural`: every word must appear in title, artist names, Instagram handle or location; ignores accents and `@`); it combines with Show and Sort.
- **Mural page** `/gallery/[slug]`: photo carousel (tap for full screen), white rounded sheet over the photo, back button, heart **like** with count (one per anonymous device), title/artist (artist names link to Instagram or another URL via the artist directory), info card (location, precision, small **Verify** pill for unverified murals with a pin, and a tag row: status, Changed, place tag, Rotating wall), Google Maps link, "Add photos / report a change", notes, **Still here / Removed / Update** buttons, comments. Photo credit is only shown while one of the credited bundled photos is still displayed. **Share** button (round, top-right of the photo; Web Share sheet, else copies the link). **Back** goes to the previous screen (admin → mural → back returns to admin; falls back to the gallery). When signed in as admin the **Update** button becomes **Edit** (opens the full editor). **Still here** on an unverified mural also sends a location-verification request to the admin (no photo/GPS; notes contain `Sent from a "Still here" tap`); the admin list groups repeated taps per mural.
- **Submit** `/submit` (opened with query params): new mural (photo **required**, location from typed address / device GPS / photo GPS / pasted map link, artist suggestions from known artists), or for an existing mural `?mural=<slug>&title=…&mode=`: `photos` (same painting or repainted, optional new name), `verify` (location verification), `update` (new mural at the same spot: optional new name + artist), none = location suggestion. Close (X) and Cancel (asks before discarding), then "Go back" / "Submit another". **Verify location needs no photo** (only a location: device GPS, photo GPS or map link). **A new mural submitted by a signed-in admin is published immediately** (verified if the pin came from device/photo GPS, otherwise unverified); everyone else's submissions wait for review.
- **Map** `/map`: pins (one solid pin style: green = verified, red = not verified; removed murals are hidden), pin card, "Take me there", search box, locate button + your position dot (auto-starts when the browser already allows location, otherwise a toast explains the button). Same top offset as every page header. **Search** lists matching murals (same matcher as the gallery); tapping one flies to the pin and opens the card, murals without a pin open their page ("no pin yet"). The pin card's photo is a swipeable carousel with dots; tapping a photo or the text area opens the mural page. Murals without `coordinates` are not on the map.
- **Tour** `/tour`: ordered stops, walking estimates, "Start in Google Maps". Stored in localStorage.
- **Menu** (logo, top-left): language, **Install the app** (full screen, no browser bar), Team sign-in/profile/admin/sign out, **Support this project** (Ko-fi), Privacy, Terms.
- **Auth** `/signin` (**team only for now**: the form asks `is_admin_email()` (migration 018) before sending a link and says "sign-in is just for admins" to anyone else; Google sign-ins from non-admins are signed straight out in `/auth/callback`): Google (button appears automatically once the provider is enabled) or emailed link. If the link is opened while already signed in (or reused), `/auth/finish` just continues to `/admin` (admins) or `/profile` instead of showing an error; the "check your email" screen also notices a sign-in done in another tab. Emailed links use the **implicit** flow (`lib/supabase/implicit.ts` → `/auth/finish` hands the session to the cookie client) so they work in any browser; Google uses the normal PKCE client + `/auth/callback`. Sessions persist (cookie, auto-refresh in `middleware.ts`).
- **Legal**: `/privacy`, `/terms` (EN/ES, Mexico-oriented; updated 2026-11-18; Terms now say tips are voluntary and non-refundable). Not lawyer-reviewed.
- **PWA**: `public/manifest.json` (standalone, maskable icons), `public/sw.js` (v2: offline fallback, caches build files and bundled photos, **push + notification click handlers**; bump `VERSION` to purge caches).

### Admin (`/admin`, owner + moderators)
- **Submissions**: guide box at the top, each card shows the submission, auto-verified / "GPS + photo" tags, the target mural's artist (with inline "Save artist" and "Edit mural" link), distance to the pin for verifications, rename/new-artist previews. Actions: Create mural… (title, artist(s) with Instagram auto-fill, location, status, precision, "Find on map from address"), Apply location…, Add photos to mural / Replace photos & tag Changed, Confirm location, Reject. **New-mural submissions from visitors are never published automatically; a new mural submitted through `/submit` by a signed-in admin is published immediately (verified if the location came from device/photo GPS).** Photos in a submission open in a **swipeable viewer** and can be **ticked** (ticked = used, none ticked = all used; unused files are not deleted from storage). Approving a **location suggestion/verification also adds the submitted photos** (placeholders replaced, else appended). Approving a **repainted** submission also marks the mural verified and moves the pin to the submission's pin. Applying a pinned location suggestion marks the mural verified (unless removed). Errors now show the real database message.
- **Murals**: full editor (title, artists via a searchable picker over the artist directory with "Create new" and a required-looking link field per artist, admin and admin/murals show a warning listing artists with no social link, status, precision, **place**, **rotating wall**, artwork original/changed, location + pin tools incl. address lookup, year/medium/notes, photo credit, photos upload/reorder). **Comments**: moderation. **Team** (`/admin/team`): add moderators by email; Owner can't be removed by anyone; moderators can add/remove other moderators. Edit page has a close (X). The artists field is **`ArtistPicker`** (search the directory, or "Create “name”"; every artist has a handle/link field and a red "no link" warning). `/admin` and `/admin/murals` show a yellow box listing artists with no social link (`lib/artistGaps.ts`).
- **Alerts**: "Enable alerts" card on `/admin` (per device/browser, iPhone needs the app on the Home Screen). A badge on the Submissions tab shows the pending count.

## 5. Data model (Supabase `public`)
- `murals`: `slug`, `title`, `artist`, `artists` (jsonb `[{name, instagram, url}]`), `artist_verified`, `location_description`, `coordinates` (jsonb `{lat,lng}`), `confidence` (`verified|unverified|removed`; **`likely` was merged into `unverified`**, still tolerated by the type/badge), `precision` (`intersection|landmark|block|area|lead`), `year`, `medium`, `notes`, `photos[]`, `cover_photo`, `photo_credit(_url)`, `artwork_status` (`original|changed`), `artwork_changed_at`, `previous_photos[]`, `artwork_history` (jsonb: earlier `{title, artist, photos, replaced_at}`), `wall_id`, `changes_often`, `place_type`, `like_count`, vote counts, timestamps. Photos starting with `/murals/` are **bundled placeholders** (files in `public/murals/<slug>/N.jpg`, `N-t.jpg` thumbnail); user photos are full Supabase storage URLs.
- `submissions`: `kind` (`new|location|photos_same|photos_repainted|verify_location`), `mural_slug`, title/artist/location/notes/photo_paths/coordinates/`location_source` (`link|device|photo|manual`), `status`, `auto_verified`, `auto_note`, `ip_hash`. (Verification submissions currently use kind `location` with a notes marker "Location verification for existing mural: <slug>"; `verify_location` is allowed only if migration 009 is applied.)
- `comments`, `votes` (one per mural per connection per day), `mural_likes` (+ `like_count`), `walls`, `artists` (directory: name, instagram, url; names are free text, existing entries use the handle as the name, e.g. `jijon_os`, until the real name is known; the junk row `unknown` is ignored by the picker and the gap warning), `admins` (`email`, `role` owner|moderator), `push_subscriptions`, `app_secrets` (server-only).
- Functions/RPC: `is_admin()`, `is_admin_email(text)` (anon-callable true/false; used by the sign-in form, migration 018), `my_role()`, `list_team()`, `add_team_member()`, `remove_team_member()`, `increment_vote()`, `set_like()`, `request_ip_hash()`, `metres_between()`, `recompute_walls()`.
- Triggers: spam guards on comments/submissions (BEFORE INSERT); `submissions_auto_verify_trg` then `submissions_notify_trg` (AFTER INSERT, in that alphabetical order); `murals_walls` (regroups murals within 20 m after insert/coordinate change).
- **Auto-verify ("only with proof")**: a submission on an existing mural with ≥1 photo and GPS from the device or the photo's EXIF within 50 m of the mural's pin verifies the location, applies the image (bundled placeholders are replaced by the first real photos; "repainted" replaces photos, tags Changed, keeps old name/artist/photos in `artwork_history`, applies an optional new name/artist) and marks the submission approved. GPS is client-reported, so this raises the bar but isn't tamper-proof. Everything else stays pending.
- **Spam limits** (per connection, via IP hash): 5 submissions/hour, 5 comments/10 min, 1 link per comment, 4 photos, size caps, 1 vote per mural per day, 30 like changes per 10 min. Your own testing counts.
- **Walls**: murals within 20 m (chained) share a `wall_id`. Two walls today: the school wall (Día de Muertos school + Mayan Man) and Maria Felix + Mayan Woman. No UI for walls yet (design decision pending).
- RLS: public read of murals/comments/artists/walls; writes admin-only (`is_admin()`); public insert of pending submissions/comments; `app_secrets`, `mural_likes`, `votes` unreadable from the API.

## 6. Design system v2 (src/styles/tokens.css + tailwind.config.ts)
Source of truth for the redesign: the design critique spec (see `docs/REDESIGN_PHASES.md`). Brand unchanged (cream, sea, Syne + DM Sans).
- **Type**: DM Sans for all UI; Syne (`font-display`) only at 20px and up. Scale classes: `text-12` (absolute minimum: tags, tab labels) · `text-13` (captions, meta) · `text-14` (secondary) · `text-16` (body, card titles; inputs are forced to 16px in `globals.css` so iOS doesn't zoom) · `text-20` (h2) · `text-28` (h1) · `text-40` (landing). The old `text-tag-sm/tag/caption/small/body/card/title` are gone. Never write `text-[Npx]`.
- **Colour**: `ink-2 #5F5A62`, `ink-3 #6F6A73` (both AA on bg and white). Status: `certain` (verified, green), `unconfirmed` (unverified AND changed, amber `#8A5608`), `removed` (purple), `danger` (red, errors/delete only; the old `guessing`/`likely` tokens were removed). New: `marigold` (+`marigold-tint`) only for the tour badge and tour tray button; `like` (filled heart). Don't use raw hex or `text-white`/`bg-white`.
- **Radius** (roles): `rounded-inset` 8 (thumbs, small chips) · `rounded-panel` 16 (gallery card photo, inputs, panels) · `rounded-card` 24 (sheets, tour list, pin card) · `rounded-sheet` 32 (mural page sheet) · `rounded-full`. **Shadow**: `shadow-1` surfaces, `shadow-2` floating (pins, sheets, tray).
- **Sizing**: `control` 44px (min tap target, round buttons) · `field` 48px (primary buttons, inputs, search) · nav bar 64px + safe area. Spacing roles unchanged (`gutter`, `grid`, `controls`, ...).
- **Components**: `ui/Tag` (one pill: DM Sans 600 12px; ConfidenceBadge, ArtworkBadge, LocationPill, PlaceTags wrap it; no `sm` size anymore) · `ui/TourButton` (Add to tour / In tour) · gallery "Create tour" multi-select (adds the picked murals to the existing tour, then opens it) · `layout/TourTray` (shows on /gallery pages when the tour has stops) · `layout/BottomNav` (64px, active pill, marigold count badge on Tour) · `layout/SideMenu` `MenuButton` (the logo inside a 44px bordered button with hover/press states, top-left of every header, opens the side menu; on desktop the logo + wordmark in the top bar does the same) · `mural/LikeButton` (`HeartIcon` on cards/pin card, `LikeButton` on the mural page: count only from 3 hearts) · `mural/MuralCard` (4:5 photo, text below, never shows coordinates).
- **Desktop (>=1024px)**: `layout/TopBar` replaces the bottom bar; Explore is two panes (cards + `mural/ExploreMap`); pins come from `lib/useMuralPins.ts` (used by the Map page and Explore); mural page is photo (60%) + info panel (40%).
- **Photos**: small copies `<name>-t.jpg` next to every photo (see `docs/REDESIGN_PHASES.md` phase 4). Use `ThumbImg` / `thumbUrl()` for anything small (cards, pins, rows); full photos only on the mural page and lightbox. Fonts come from `next/font` (`--font-syne`, `--font-dm-sans`).
- **Helpers**: `lib/format.ts` (`displayTitle` title-cases all-lowercase titles, `displayArtist` strips @ and de-duplicates, `displayPlace` hides "Pinned location (lat, lng)", `walkMinutes` = 80 m/min) · `lib/likes.ts` (`useLikes`: hearts on this device = "Saved") · `lib/tour.ts` (`useTour`, `shortestOrder`, `buildGoogleMapsUrl(stops, fromMyLocation)`).
- **Map pins**: 40px photo circles in 44px buttons (aria-label "title, artist"), solid ring green = verified / amber = unconfirmed, selected 60px with a sea ring, pins closer than 48px are grouped into a dark count circle (tap zooms in), map pans so the selected pin stays above the pin card. No legend, no chips (owner decision).
- **Tour**: Edit mode holds reorder (up/down) and delete; "My location" chip starts the Google Maps route from where you are; "Shortest order" = nearest-neighbour; share link `/tour?stops=slug1,slug2` rebuilds the tour (replaces the saved one).
- i18n: every public string is in `lib/i18n/dict.ts` (EN + ES, typed keys); locale in the `locale` cookie. Naming: Explore (route still `/gallery`), Map, Tour, Add mural, "Send for review", "Unconfirmed" (was Unverified), "Directions".

## 9. Gotchas learned the hard way
- `supabase/functions/` (Deno) is **excluded from `tsconfig.json`**; including it broke the Next build and the production deploy once.
- `@supabase/ssr` forces the PKCE flow, so emailed links opened in a different browser fail with "code verifier not found". That's why email links use `createImplicitClient()` and `/auth/finish`. Emailed links are single use (a second use shows an error unless you're already signed in).
- Supabase's built-in email: `429 over_email_send_rate_limit` after a few emails/hour (custom SMTP is the fix).
- **Supabase's API role rejects `DELETE`/`UPDATE` without a `WHERE`** ("DELETE requires a WHERE clause", 21000). Tests run as `postgres` or with `set_config('role', …)` inside a DO block do **not** show it; a function that deletes everything from a temp table needs `where true` (this broke every save that touched a pin until migration 017). Supabase-error objects are not `Error` instances; use `lib/errors.ts` `errMsg()` so the real message is shown.
- The Supabase SQL tool asks the user to confirm any statement containing `delete`/`drop`/`truncate`; unanswered for 60 s it times out. Write around it or give the owner SQL for the dashboard. A multi-statement call is one transaction. `execute_sql` only returns the **last** statement's rows.
- Test DB changes in a `do $$ … raise exception 'ROLLBACK_TEST %', r; end $$` block. IP-based limits read `request.headers` (`set_config('request.headers','{"x-forwarded-for":"203.0.113.7"}', true)`).
- Vercel Hobby keeps runtime logs for 1 hour; Supabase auth logs show sign-in failures (UTC; the owner is UTC−5). The agent sandbox cannot reach vercel.com, DNS tools, geocoders or map tiles; the Vercel MCP can edit DNS records and list deployments.
- Server-side pages call Supabase from the server, so Playwright `page.route` can't stub them; to test client components render them on a temporary `/tt` page with fake data (delete it afterwards).
- A mural without coordinates isn't on the map. `revalidate = 30` on the mural page, so changes can take ~30 s to show.
- **The domain is spelled `murles-pdc.art`** (no "a"); the owner sometimes types "murales" — email addresses and DNS must use `murles`.
- Don't write `rounded-xl`/`text-white`/raw hex: the config only has role tokens now (see §6); `rounded-md/lg/xl/sm` no longer exist.
- GitHub PRs are made with the GitHub MCP tools (no `gh` for PRs); a PR needs the owner's explicit "merge". Pushing to a branch other than the session's assigned one is not allowed.
- Test submissions you create in production are real rows; reject them in `/admin`.
